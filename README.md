# Dayresi

登録不要・その日だけ使える Web レジ。文化祭の模擬店のように、一日だけレジが欲しいときに使います。1 台の PC で使うことも、何人かがそれぞれのスマホで会計して、代表者が売上をまとめることもできます。

**https://shunsukenaka.github.io/Dayresi/**

## なぜ作ったか

大学の文化祭で出店するときは、アプリを作り慣れた人がレジを作るか、現金と紙で管理していました。既存の POS アプリは登録や契約が必要で、一日だけ使うには大げさです。Dayresi は、登録も契約もせず、直前に決まった商品をすぐ登録してレジを用意できるようにします。迷ったときは手軽さを優先し、便利でも手順が増えるものは足しません。

文化祭では、わざわざ PC で会計せず、何人かが自分のスマホで会計する屋台も多くあります。そこで、代表者が商品を配り、会計した人が代表者に会計を送って、代表者の端末でまとめられるようにしました。サーバーは使いません。

目的や届けたい人の詳しい内容は [docs/mvp-design-doc.md](docs/mvp-design-doc.md)、仕様は [SPEC.md](SPEC.md)（MVP）と [docs/spec-next.md](docs/spec-next.md)（代表者が集計する方式・スマホ対応）を参照してください。

## できること

### レジとして

- **商品の登録**：商品名と価格（税込）だけを登録する。割引券は「割引 −50円」のように、マイナスの価格の商品として登録できる
- **会計**：商品ボタンを押してカートに入れ、数量を増減する。カートに入っている商品のボタンには数量が出る。画面のテンキーや金額ボタンでお預かり金額を入れると、おつりを表示する
- **会計の取消**：確定したあとの会計を、履歴から取り消せる。取り消した会計は「取消済」として残り、集計には入らない
- **集計**：売上合計・会計件数と、商品別の数量・金額・売上に占める割合を見られる
- **CSV の保存**：売上明細を CSV で保存できる（Excel で開いても文字化けしない）
- **全データの消去**：今のレジの商品と会計をすべて消せる

### 何人かで使うとき

- **レジの切り替え**：1 台の端末でレジ（店ごとの商品と会計のまとまり）をいくつも持ち、画面の上で切り替える
- **商品を配る**：代表者が登録した商品を、QR コードかリンクで会計する人に配る。配られた商品は、受け取った側では編集できない
- **代表者に送る**：会計する人が、自分の会計を QR コードかリンクで代表者に送る
- **自動で合算**：代表者の端末で QR を読むかリンクを開くと、受け取った会計が自動で売上に足される。何回送り直しても二重にならず、会計した人が取り消した会計は代表者の側でも取消済になる。履歴には「田中 #2」のように会計した人の名前が付く

在庫管理、割引・セット価格、レシートの発行、支払方法の区別などはありません。

## 使い方

### 1 台で使うとき

1. **準備**：「設定」で商品を登録する
2. **当日**：「レジ」で商品を選び、「会計」でお預かり金額を入れて「会計確定」を押す。お預かり金額を入れずに確定すると「ちょうど」として扱う。間違えたら「履歴」で取り消して打ち直す
3. **終了後**：「集計」で売上を確認し、「設定」の「売上CSVを保存」でファイルに残す。使い終わったら「全データを消去」で消す

### 何人かで使うとき

1. **代表者が準備する**：画面の上のレジの名前を押し、「レジを追加 → 新しいレジを作る」で、レジの名前（例：研究室の模擬店）と自分の名前を入れて作る（最初からある「マイレジ」を使ってもよい）。「設定」で商品を登録し、「商品を配る」を押す
2. **会計する人がレジを追加する**：代表者の画面の QR をスマホのカメラで読むか、送られたリンクを開く。自分の名前を入れて「追加する」を押す
3. **当日**：それぞれの端末で、1 台で使うときと同じように会計する
4. **代表者に送る**：会計する人は、交代するときや終わったときに「設定」の「代表者に送る」を押し、QR を代表者に読んでもらうか、リンクを LINE などで送る。何回送ってもよい
5. **代表者がまとめる**：代表者は、QR を読むかリンクを開くだけで売上に足される。「集計」で全員分の売上を確認し、「売上CSVを保存」でファイルに残す

商品を足したときは、代表者が「商品を配る」で配り直し、会計する人は読み直します（それまでの会計は残ります）。

## データと動作環境

- アカウント登録はいりません
- データは、その端末のブラウザ内（localStorage）にだけ保存します。サーバーには送りません
- 端末のあいだでは、QR コードとリンクでだけデータを渡します。データはリンクの `#` より後ろに入るので、サーバー（GitHub Pages）にも届きません。自動で同期することはありません
- 同じ端末でも、ブラウザが違うとデータは別になります（iPhone では、ホーム画面に追加した Dayresi と Safari でも別になります）
- 一度ページを開けば、インターネットにつながらなくても会計できます。リンクを LINE などで送るときは、そのアプリの通信が要ります
- PC（マウス）でもスマホ（タップ）でも使えます。今あるレジ・履歴・集計・設定の画面は、PC 向けの並びのままです
- 商品を配る・代表者に送るには、Safari 16.4 以降か Chrome 103 以降が要ります

## 開発

Node.js 24 が必要です。

```sh
npm install
npm run dev      # 開発サーバー
npm test         # ロジックのテスト
npm run build    # dist/ に静的ファイルを出力
npm run preview  # ビルド結果の確認（オフライン動作もここで確認できる）
```

## 公開（GitHub Pages）

1. GitHub にリポジトリを作って `main` ブランチを push する
2. リポジトリの Settings → Pages → Build and deployment の Source を「GitHub Actions」にする
3. 以降は `main` に push するたびに `.github/workflows/deploy.yml` がテスト・ビルド・公開を行う

`base: './'` にしているので、リポジトリ名を変えても設定変更は不要です。
