# 0031. 作り直しの Issue を Design Doc に合わせて立て直し、SPEC にない機能は作らない

- 日付: 2026-10-25
- 状態: 採用

## 背景

作り直しの Issue（旧 #15〜#45）は、Design Doc（0026）をまとめる前に立てていた。そのため、SPEC にも Design Doc にもない項目（保存できなかったときの知らせ、壊れたデータの退避、取消の件数、CSV インジェクション対策など）や、Design Doc と食い違う項目（#11 の扱い）が入っていた。今のコードにも、SPEC にない機能が残っていた。Issue をどう直すかと、SPEC にない機能をどう扱うかを決める必要があった。

## 決めたこと

- 旧 #15〜#45 を閉じ、Design Doc から Issue を立て直す（#50〜#77）。Design Doc は MVP を考えたときの記録なので変えず、古い番号もそのまま残す
- SPEC にも Design Doc にもない機能は作らない。今のコードにあるものも消す（#50）。足したいときは、先に SPEC を直す
- その一つとして、商品の編集・削除・並べ替えを消し、登録だけにする。SPEC の「MVP で扱わないもの」に書く
- 同じく、会計を確定したときのトーストも消す

## 検討した他の案

- Issue の扱い：今の Issue（#15〜#45）の本文を書き直し、足りない Issue だけ新しく立てる
- SPEC にない項目：残す項目を 1 つずつ選ぶ
- 商品の編集・削除・並べ替え：すべて SPEC に足して残す／編集・削除だけ SPEC に足し、並べ替えは消す
- トースト：SPEC に足して残す
