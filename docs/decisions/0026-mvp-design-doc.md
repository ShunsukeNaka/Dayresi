# 0026. MVP を考えたときの内容を Design Doc にまとめ、docs/ に置く

- 日付: 2026-10-23
- 状態: 採用

## 背景

MVP は、ユーザージャーニーマップで困りごとを洗い出し、SPEC を見直して決めた（0011〜0019）。その経緯はユーザージャーニーマップ、SPEC.md、ADR、Issue に分かれていて、MVP を「なぜこの形にしたか」を一か所で読めなかった。作り直し（0022）を始める前に、Design Doc を作るかと、作るなら何を書いてどこに置くかを決める必要があった。

## 決めたこと

- MVP を考えたときの内容（目的、届けたい人、困りごと、やること・やらないことと、その理由）を Design Doc にまとめる。新しく決めることは書かない
- `docs/mvp-design-doc.md` に Markdown で置く
- データの形式の Issue（#15）より前に終わらせる

## 検討した他の案

- 書く内容
  - 実装の全体像（層の分け方、データの流れ、主な型と関数）だけを書き、細かいことは #15〜#32 で決める
  - データの形式とロジックの関数の仕様まで Design Doc で決め、#15〜#32 は実装だけにする
  - 作らない
- 置き場所：Claude Docs（claude.ai の共有ドキュメント）

## 理由
MVPで何を作るのかをまとめた資料が欲しかった。
これがないと判断ができない。
