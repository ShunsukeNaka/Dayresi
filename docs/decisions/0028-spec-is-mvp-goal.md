# 0028. SPEC は MVP の目標として扱う

- 日付: 2026-10-23
- 状態: 採用（「MVP のあとでやることは SPEC の『MVP で扱わないもの』に書く」の部分は 0033 で置き換え）

## 背景

MVP の完了条件は「SPEC の通りに実装され、GitHub Pages で公開されている」こと（0014）。Design Doc（0026）でこの条件を見直したとき、SPEC がプロダクト全体の最終目標なのか、MVP の目標なのかがはっきりしていなかった。また Design Doc の書き方では、今この条件を満たしているように読めた。

## 決めたこと

- SPEC は MVP の目標として扱う。MVP のあとでやることは、SPEC の「MVP で扱わないもの（今後の検討事項）」に書く
- MVP の完了条件（0014）は変えない
- Design Doc には、完了条件をまだ満たしていないことと、#45 で確かめることを書く

## 検討した他の案

- SPEC をプロダクト全体の最終目標として扱い、MVP の完了条件を別に決め直す（0014 を置き換える）

## 理由
改めてSPECの役割を明確にしたかった。
