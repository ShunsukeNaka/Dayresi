# 0023. Issue の作業中に決めたことは、ADR ではなくその Issue に書く

- 日付: 2026-10-19
- 状態: 採用

## 背景

Issue 駆動で開発することにした（0021）。Issue の作業中に決めたことを、ADR に書くか、その Issue に書くかを決める必要があった。

## 決めたこと

- Issue の作業中に決めたことは、その Issue にコメントで書く（示した選択肢、決めたこと、理由）。ADR には書かない
- 理由はユーザーが書く。Claude は推測で書かない
- ただし、Issue の作業中でも、プロダクト全体にかかわる判断（開発の進め方、プロダクトの思想など）は ADR に書く
- Issue の外で決めたことは、今までどおり ADR に書く（0001）

## 検討した他の案

- ADR は今までどおり書き、その Issue にもコメントで書く
- 意思決定は Issue に書き、ADR をやめる
- 選択肢や理由のやりとりは Issue で行い、結論だけを ADR にまとめる
- ADR は大きな判断だけにし、細かい判断は Issue に書く

## 理由
- ADRにまとめていっても良いのだが、機能などはISSUEに切り出されることが前提になっているにのでそれらの意思決定はISSUEに書いていくことにする。
- 今後は、ISSUEに切り分けられていないような全体にかかわるようなものをここにまとめていく。
  - プロダクトの思想など
