# 0021. Issue 駆動で開発する

- 日付: 2026-10-19
- 状態: 採用

## 背景

MVP の完了条件（0014）を満たし、これから開発を続けていく。作業の始め方と、Issue・ブランチ・PR のつなげ方を決める必要があった。

## 決めたこと

- 作業は Issue を立ててから始める。誤字など、振る舞いも仕様も変わらない小さな修正だけは Issue なしで PR を出してよい
- Issue は基本的にユーザーが立てる。Claude が立てるときは提案して承認を得る。ただし、まとめて立てるように頼まれたときは、1件ずつ確認せずに立ててよく、あとで一覧で報告する
- Claude は、ユーザーが番号を指定した Issue にだけ取りかかる
- ブランチ名に Issue 番号を入れる（例：`fix/11-mobile-layout`）

## 検討した他の案

- どんな作業も、小さな修正を含めて先に Issue を立てる
- Claude が見つけた問題は、確認なしで Issue を立ててよい
- Claude は問題を報告するだけで、Issue は立てない
- 開いている Issue から、次にやるものを Claude が選んで提案する
- ブランチ名に Issue 番号を入れない（今までどおり。つながりは PR の本文で示す）
