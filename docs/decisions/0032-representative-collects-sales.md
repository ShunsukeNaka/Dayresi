# 0032. 次の段階では、代表者が商品を配り、会計を受け取って合算する方式で、端末のあいだでデータを引き渡す

- 日付: 2026-10-26
- 状態: 採用

## 背景

文化祭では、何人もが自分のスマホで会計することが多い。MVP は「PC 1 台」を前提にし、端末のあいだでデータを共有する機能は扱わないことにしていた（0027）。そこで、端末のあいだでデータを引き渡せるようにするか、するならどんな方式にするかを決める必要があった（#124）。

## 決めたこと

- MVP の次の段階で、端末のあいだで商品と会計を引き渡せるようにする。MVP の範囲（0027）は変えない
- 代表者が集計する方式にする
  - 代表者が商品を登録し、会計する人に配る。会計する人の端末では商品を登録できない
  - 会計する人は、配られた商品で自分の端末で会計し、自分の会計をすべて代表者に送る
  - 代表者の端末は、受け取った会計を自動で合算する。会計の ID で同じ会計を見分け、二重にしない
- サーバーも DB も持たず、常に情報を送り続けない。商品の配布と会計の送信は、どちらも QR コードとリンク（データは URL の `#` 以降）で行う
- 取消は会計した端末でだけ行い、送り直すと代表者の端末でも取消済になる
- 会計番号が端末ごとに重なるので、各端末に名前を付け、代表者の履歴では「田中 #3」のように出す
- スマホでも使えるようにする
- 仕様は [docs/spec-next.md](../spec-next.md) に書く（0033）

ユーザージャーニーマップ（PC 1 台をみんなで使う、スマホアプリは合わない）とは食い違うが、スマホで会計する場面があることと、わざわざ PC で会計していない屋台が多いことは、ユーザー自身の体験で確かめている。

## 検討した他の案

- 交代するたびに、前の人の端末から次の人の端末へ、QR コードで会計をリレーする（それぞれの人の責任が大きく、誰が最新版を持っているか分かりにくい）
- 交代するたびに、集計の結果だけを渡す
- 送る操作をなくし、自動で同期する（自分のサーバーと DB を置く、外部の無料サービスを中継に使う、Google スプレッドシートなどに書く、同じ Wi-Fi の中で WebRTC でつなぐ）。どれも「サーバーも DB も持たない」「アカウント登録をしない」「常に送り続けない」のどれかとぶつかる
- 送り方：ファイル（AirDrop・LINE など）だけ、QR コードだけ、リンクだけ
- 別々の端末で登録した同じ商品を、名前と価格でまとめる／別々のままにする
- 代表者も、受け取った会計を取り消せるようにする
- 会計番号を、そのまま重なってよいことにする／取り込むときに振り直す
- 画面は PC 向けのままにする
- 次の段階ではなく、MVP に入れる
