## 主人公とシナリオ

- 主人公：大学の文化祭で模擬店を出す学生。次の2つの役割を並べる
  - **用意する人**：準備の段階でレジを選んで用意し、集計・報告まで受け持つ
  - **接客する人**：当日、接客したその場でレジを操作して会計する
- シナリオ：出店が決まってから、終了後の報告・片付けまで
- 情報源：
  - 開発者自身の出店経験（研究室のメンバー5人ほどで模擬店を出店）。開発者は用意する人で、当日の会計もいちばん長く受け持った

## 分かったこと（困りごと以外）

- 操作は商品を選んで個数を入れるだけなので、使い方を覚える必要はほとんどなかった。使い方についての質問は、間違えたときの直し方くらいだった
- 作った本人も他のメンバーと同じくらい間違えたので、間違いの原因は使い方に慣れていないことだけではない
- 間違いには会計の直後に気づくことがほとんどだった。直し方は「直前の会計を取り消して打ち直す」のが一番楽
- 当日は混む時間帯は特になかった
- 接客する人が会計で特に気をつけていたことはなかった。お客さんは、店員がアプリで会計していることに気づいていないと思われる
- レジはインターネットを使わないので、当日の朝にネットや起動の準備をする必要はなかった
- 売上の CSV は代表に送った。報告を担当したのが代表かどうかは分からない
- PayPay で受け取った分も、支払方法を分けずに記録した。それで困ったことはなく、現金と記録のずれもなかった
- 2つの店舗を出し、店舗ごとに別のレジを使った。もう片方の店舗のレジは別のメンバーが作り、整理番号を出すためにレシート機を使った
- 割引券は、2つの店舗の両方に来てもらうために研究室で独自に用意したもので、「会計から一律50円引き」。SPEC 通り割引を扱えない Dayresi なら使わないが、「割引 −50円」を商品として登録するような代用で足りる
- 割引した件数・金額をあとで数える必要があったかは分からない
- 報告を担当する人が別にいた。報告フォーマットの項目はまだ分かっていない

## 困りごとと Dayresi での対応

| 困りごと | フェーズ | Dayresi で対応するか | 理由・SPEC との関係 |
|---|---|---|---|
| 合うレジがないので、作れる人が自分で作るしかない（全体で一番面倒だった） | レジの準備 | 対応する（SPEC は変えない） | Dayresi の中心となる価値。「登録不要」「PC 1台」「自動計算」は SPEC の前提と合っている |
| 商品の構成と価格が直前に決まるので、商品の登録も直前になって面倒 | レジの準備 | 対応する（SPEC は変えない） | 登録するのは商品名と価格だけなので、直前でも設定画面で手早く登録できる。別の端末で登録して設定ファイルで持ち込む「事前準備」もある |
| 入力の間違いが2割ほど起き、直せるのはレジを作った人だけ | 当日の会計 | 対応する（SPEC は変えない） | SPEC の「確定後の会計を取り消せる」で、接客する人も履歴から取り消せる。打ち直しは手で入れ直す。取り消した会計をカートに戻す機能は足さない（[ADR 0012](../decisions/0012-keep-void-as-is.md)） |
| 「割引」ボタンを押し忘れる（割引券がある） | 当日の会計 | 代用で対応する（SPEC を変える） | 割引機能は「MVP で扱わないもの」のまま。商品の価格をマイナスにもできるようにし、「割引 −50円」を商品として登録して代用する（[ADR 0011](../decisions/0011-allow-negative-price.md)）。押し忘れそのものは防げない |

## SPEC で決めること

ヒアリングで出てきた、SPEC.md を変えるかどうか決める必要があったこと。

- 商品にマイナスの価格を登録できるようにするか → できるようにする（[ADR 0011](../decisions/0011-allow-negative-price.md)）。SPEC.md を更新した
- 確定後の会計の取り消しを、どこまで簡単にするか → 今の取消のままにする（[ADR 0012](../decisions/0012-keep-void-as-is.md)）

## ヒアリングで確かめること

過去に出店した人に聞いて、上の「？」と、SPEC の前提が合っているかを確かめる。

- 誰がレジを用意したか。会計の担当を決めたか
- レジに何を使ったか（紙、電卓、アプリ、端末は PC かスマホか）と、それを選んだ理由
- 割引券・セット価格・トッピングなど、価格が変わる売り方をしたか。割引した件数・金額をあとで数える必要があったか
- 会計を間違えたとき、誰がどうやって直したか
- キャッシュレス決済を受けたか。受けた場合、記録や現金をどう扱ったか
- 終了後に現金と記録を照らし合わせたか。合ったか
- 複数の店舗を出したか。出した場合、レジや売上をどう分けたか
- 学祭実行委員への報告フォーマットに、どんな項目があったか（自分の出店の報告担当に聞くことは、いったん保留）
- 一番大変だった、または面倒だった場面と、そのときの気持ち
