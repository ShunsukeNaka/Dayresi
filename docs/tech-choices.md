# 技術の選択

選んだ技術ごとに、メリットと、ほかの案を選ばなかった理由を書き足していく（[ADR 0029](decisions/0029-record-tech-choices.md)）。決めた経緯や理由（ユーザーが書くもの）は、各 Issue のコメントや ADR を見る。

## 商品の ID：`crypto.randomUUID()`

- 決めた Issue：[#51](https://github.com/ShunsukeNaka/Dayresi/issues/51)
- 使う場所：商品を登録するときに振る ID

### メリット

- ブラウザの標準機能なので、npm パッケージを足さずに使える
- 122 ビットの乱数から作るので、実際には重ならない。登録した順番や時刻に左右されない
- 「一番大きい番号＋1」のように今ある商品を見て決める必要がないので、振る処理が商品の一覧に依存しない

### ほかの案と、選ばなかった理由

| 案 | 選ばなかった理由 |
|---|---|
| 今の方式（`Date.now()` の 36 進数＋`Math.random()` 6 文字） | 同じミリ秒に 2 つ振ると、乱数 6 文字だけで区別することになる。標準の UUID のほうが重ならないことがはっきりしている |
| 1 からの連番 | 人が読めるが、商品 ID は画面に出さないので読めることに意味がない。振るたびに今ある商品の最大値を探す必要がある |

### 注意

- 安全なページ（HTTPS か `localhost`）でしか使えない。GitHub Pages（HTTPS）と `npm run dev`・`npm run preview`（`localhost`）では動くが、ほかの端末から `http://192.168.…` で開くと動かない
